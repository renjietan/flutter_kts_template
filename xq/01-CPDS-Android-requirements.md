## 2. 产品定位与范围

CPDS Android 是安装在 Android 手机或平板上的通信保障配置包下发工具。设备通过同一二层广播域内的 Wi-Fi 或有线以太网接入业务网络，完成通信包导入、解析、当前节点选择、CPDC 发现、认证、广播传输、解析结果展示和失败原因提示。

CPDS Android 采用 Flutter + Dart 技术栈，并复用 CPDS 既有业务规则和 Proto 协议：

- 当前工程基线：Flutter 3.38.10、Dart SDK `^3.10.9`、Gradle 8.14-all、AGP 8.11.1、Kotlin 2.2.20。
- 应用包名为 `com.hytera.cpd`，应用显示名为 `CPD`。
- Flutter UI 负责页面、用户操作和实时状态展示，不直接解析 Proto 报文，也不直接读写底层 UDP 字节流之外的业务数据。
- Dart 服务层负责通信包解析、UDP 协议、会话状态机、文件传输、日志和状态订阅。
- Proto 编解码使用 `protobuf` 包生成的 Dart 类，与 CPDS/CPDC 双方约定的 `cpd.proto` 保持相同 `package`、消息结构、字段号和枚举值，不新增 Android 专属业务字段。
- 文件选择使用 `file_picker`，ZIP 解压与重建使用 `archive`，网络接口枚举使用 `network_info_plus` 或等效平台通道，UDP 收发使用 `udp` 或等效 Dart 网络能力。
- 本地持久化可使用 ObjectBox，会话结果、失败明细和脱敏日志保存在应用私有目录，不写入共享存储。
- Android 版不要求启动外部浏览器，也不提供 `CPDS-CCU` 网页端口。若保留本地调试用 `shelf` HTTP 服务，只允许监听 `127.0.0.1` 回环地址，不得暴露到业务网络。

发布文件：

|---|---|---|---|
| `app-release.apk` 或按 ABI 拆分产物 | Android | `flutter build apk --release --split-per-abi` | Flutter Android 应用 |

本期左侧菜单仅显示并激活“参数加注”。“电台管理”“密钥管理”等入口隐藏且不提供业务功能。

本期功能范围：

## 3. 部署与网络前提

- Android 设备必须与目标 CPDC 处于同一二层广播域。可通过同一业务 Wi-Fi、USB 以太网适配器或其他 Android 可枚举的有线网络接入；蜂窝数据、VPN、热点共享和常见虚拟接口不得作为业务广播出口。
- CPDS Android 本身不充当 CPDC、CCU、Server 或其他逻辑设备，也不在本机运行独立的 CPDC 进程；本机设备下发不适用 Android 版本。
- 设备初始 IPv4 地址可以不在同一网段，但必须能够把 UDP 受限广播发送到 `255.255.255.255`。
- CPDS 后端使用 IPv4 受限广播地址 `255.255.255.255` 与 CPDC 通信。
- CPDC 固定接收 UDP 端口为 `39001`，CPDS 固定接收 UDP 端口为 `39002`。
- Android 版不提供对外 TCP 网页端口。若启用调试用本地 HTTP 服务，只监听 `127.0.0.1`，不参与 CPDS—CPDC 交互。
- Android 只通过连接业务网络的候选接口收发协议报文。候选接口必须满足：已启用、具有非环回且非链路本地 IPv4、属于 Wi-Fi 或 USB/有线以太网、不属于蜂窝、VPN、热点共享、容器或虚拟接口。接口名称不属于 CPD 协议字段，不得硬编码在业务代码中。
- Android 版通过页面枚举候选业务接口。只有一张候选接口时自动选择；存在多张候选时优先恢复本机 `SharedPreferences` 键 `cpds.networkInterface` 中仍然有效的接口标识，否则等待用户选择。没有有效选择时不得开始 Distribution。
- 接口枚举失败或没有候选接口时，前端统一显示当前语言的 `NETWORK_INTERFACE_ERROR`，不得显示 `INVALID_MESSAGE`。
- Android 发送 UDP 广播前必须确保套接字开启广播能力。若候选接口为 Wi-Fi，还应按系统要求获取 `WifiManager.MulticastLock` 或等价机制，避免 Android 忽略广播/组播报文；释放时机与会话结束或网络切换一致。广播能力初始化失败、MulticastLock 获取失败或接收套接字绑定失败均包装为 `NETWORK_INTERFACE_ERROR`。
- Android 应用声明并运行时申请：`INTERNET`、`ACCESS_NETWORK_STATE`、`ACCESS_WIFI_STATE`、`ACCESS_LOCAL_NETWORK`，以及运行 Android 17（API 37）及以上设备所需的本地网络权限。不得使用位置权限替代本地网络权限，也不得在未获授权时静默降级为无网络状态。
- 每次 Distribution 开始时，冻结本次会话使用的单一业务接口快照；活动会话期间不得切换接口。刷新页面或接口失效后，按“单候选自动选择—有效持久化值恢复—等待用户选择”的规则重新确定。
- Android 接收端以普通 UDP 套接字监听 `0.0.0.0:39002`，不读取也不依赖报文到达网卡索引，不按入站网卡过滤；报文内容不携带网卡名称。
- CPDS 每次逻辑发送仍无条件把完全相同的协议报文额外发送一次到 `127.0.0.1:39001`，保持与 Windows/CCU 版一致的协议行为；Android 上不部署本机 CPDC，环回副本失败只记录告警，不影响远端 Distribution。业务接口发送成功时，环回失败不得立即终止会话。
- 接收端先校验 Magic 并反序列化 Proto，再只接受当前有效 `session_id` 且符合当前阶段消息类型的报文；设备回复还必须匹配发现或认证形成的设备类型、ESN 和设备 ID 绑定。其他会话、未知设备、错误阶段、非法 Magic 或非法 Proto 报文直接丢弃，不更新状态。
- Android 套接字在初始化、广播、环回或接收时产生的所有系统错误统一包装为 `NETWORK_INTERFACE_ERROR`，不得降级为 `INVALID_MESSAGE`。
- 系统部署时应放行双方约定的 UDP 端口，并确认 Wi-Fi AP、交换机 VLAN、端口隔离和 USB 以太网网桥规则不会阻断广播。
- 本项目运行在物理隔离且可信的节点内部广播网，不要求对广播报文和通信包另行加密或进行密码学身份认证。CRC32 和 SHA-256 仅用于传输完整性校验，不作为安全认证机制。
- 同一二层广播域在任一时刻只能有一个 CPDS 执行 Distribution，并且只能接入当前待下发节点所属的设备。其他节点设备或第二个 CPDS 同时存在会导致额外设备、认证归属或会话竞争，本期不提供跨节点仲裁机制。
- Android 活动 Distribution 必须作为前台服务运行，显示常驻通知，确保 Doze、应用待机或用户切换应用时不会中断 UDP 会话。通知内容只包含进行中的状态文案，不得显示 ESN 全文、密码或原始通信包内容。

## 4. UI 设计规范

### 4.1 总体布局与响应式

以 Figma 1366×768 画布为业务布局基准，同时适配 Android 手机和平板：

| 区域 | 桌面基准 | Android 适配要求 |
|---|---:|---|
| TopBar | 1366×40 px | 保持 Logo 和品牌名称；品牌名称旁显示由 `version.json` 提供的四段式产品版本，格式为 `CPD V<主版本.次版本.修订版本.构建版本>`；不提供系统窗口按钮 |
| 左侧菜单 | 112×728 px | 手机使用侧滑抽屉或底部导航，仅显示“参数加注”并保持激活；“电台管理”“密钥管理”等入口隐藏 |
| 左侧功能区 | 717×728 px | 手机纵向以单列卡片呈现；平板/横屏可用左右分栏，左区为文件导入、解析和节点树 |
| 右侧状态区 | 536×728 px | 手机纵向放在内容下方或独立页签；平板/横屏与左区并排显示当前节点、流程阶段和设备状态 |

响应式规则：

- 视口较窄（逻辑宽度小于 600 dp）时，优先单列滚动，节点树与设备状态通过分段卡片或页签切换；不得同时挤压左右区域导致文字溢出。
- 视口较宽（逻辑宽度不小于 600 dp）时，优先保持左右分栏布局，左区与右区可独立内部滚动。
- 使用 `flutter_screenutil` 或等效方案按设计尺寸缩放间距、字号和圆角，不得使用散落的硬编码像素覆盖。
- 横竖屏切换、折叠屏或窗口尺寸变化时，已解析的通信包、当前节点、会话状态和结果不得丢失；不允许因此重启 Distribution。

### 4.2 左侧文件导入区

左侧功能区保持业务结构：

1. `File parse` 标题。
2. 已选择的原始文件名显示框；Android 不得显示或依赖客户端原始完整路径。
3. `Browse` 按钮：通过系统文件选择器选择 ZIP 文件，只允许选择 ZIP，并将文件复制到应用私有临时目录。
4. `Parse` 按钮：复制成功后，校验并解析应用保存的临时副本。
5. `Net Node` 区域：显示包内解析出的组织和网络节点树。

解析前不得显示旧通信包的节点结果。解析失败时保留已选择的原始文件名，并显示可定位的失败原因。文件选择使用 Android Storage Access Framework 或 `file_picker`，不得要求 `MANAGE_EXTERNAL_STORAGE` 或读取用户完整目录树。

### 4.4 右侧设备列表与通信包数据映射

选择节点后，CPDS 读取该节点的 `SystemConfiguration` 并按展示设备类型呈现设备引用；除 `CCU` 与 `CCUAudio` 共同归入一个“CCU”分组外，其余设备按逻辑设备类型分组。每个引用对应 `3_device_config/<设备ID>.json`。

| 包内配置位置或型号 | CPDS 逻辑设备类型 | CPDC 类型枚举 |
|---|---|---|
| `LANPrimary.Server`中的 `dc_server_*` | Server | `Server` |
| `LANPrimary.Server`中的 `dc_IEC_*` | IEC | `IEC` |
| `LANMember.CCU` | CCU-Main | `CCU` |
| `LANMember.CCU` | CCU-Audio | `CCUAudio` |
| `Radio.MMR200` | MMR200 | `MultiBandRadio` |
| `Radio.PMR200` | PMR200 | `MultibandHandheld` |
| `Radio.MR9360` | MR9360 | `HF` |
| `Radio.PRR206` | Small Handheld | `SmallHandheld` |

其中 HF 设备文件名匹配 `dc_MR9360_*.json`，SmallHandheld 设备文件名匹配 `dc_PRR206_*.json`。IEC 和 Server 都使用 `SystemConfiguration.LANPrimary.Server` 数组，但在同一节点内互斥：该数组只能引用 `dc_IEC_*` 或 `dc_server_*` 中的一种前缀，不能同时出现。CPDS 分别将两种前缀映射为 IEC 和 Server；前缀不匹配任何已知类型或同一节点同时包含两种类型时，通信包解析失败。

样例 A车节点 `nn_vehicle_1001010000` 的右侧数据为：

- `dc_MMR200_683771630`：来自 `Radio.MMR200`
- `dc_ccu_10.64.0.1`：来自 `LANMember.CCU`，自动展开为共享该原始设备 ID 和配置文件的 `CCU-Main` 与 `CCU-Audio` 两个逻辑设备
- `dc_server_683771570`：来自 `LANPrimary.Server`

### 4.5 右侧状态区

右侧采用“按展示设备类型分组的紧凑状态卡片”方案，并保持 Figma 的尺寸、边框、背景和行高体系。`CCU-Main` 与 `CCU-Audio` 作为两行共同显示在同一个“CCU”分组内。

右侧顶部显示：

- 当前节点名称。
- 已上线逻辑设备数/期望逻辑设备数。
- Android 版本在当前节点标题栏下方显示一行“业务接口”控件，顺序固定为标签、接口下拉框、“刷新”按钮和节点级“下发”按钮。该行保持紧凑布局，新增控件不得改变标题栏、阶段条、进度条、设备卡片及其他既有控件的样式。
- 阶段条：发现、认证、传输、解析、完成。

Android 业务接口控件遵循以下行为：

1. 页面启动时通过平台层重新枚举当前已启用、具有私有 IPv4、且不属于蜂窝/VPN/虚拟/环回接口的候选 Wi-Fi 或有线接口，Flutter 页面不直接访问系统网络接口细节。
2. 下拉项显示接口名称和 IPv4 地址。只有一张候选时自动选中并显示“自动选中”；多张候选时，若 `cpds.networkInterface` 保存的接口标识仍在候选列表中则自动恢复，否则保持未选择状态并禁用“下发”。
3. 用户选择接口后立即通知 Dart 服务层更新待用接口，并将接口标识写入 `SharedPreferences` 键 `cpds.networkInterface`。只保存接口标识，不引入额外数据库表。
4. 点击“刷新”重新枚举候选列表：当前选择仍有效时保持不变；失效时重新执行“单候选自动选择—有效持久化值恢复—等待用户选择”的规则。枚举或选择失败时通过统一 `ErrorCode` 和三语错误弹窗显示具体原因。
5. 点击“下发”时 Dart 服务层使用当前选择创建本次单接口 UDP 传输；会话开始后冻结该接口。活动 Distribution 期间下拉框和“刷新”按钮禁用，不能切换会话接口。
6. 接口名称不写入通信包、Proto 报文、节点数据或会话消息。

每个设备项显示：

- 包内设备类型及型号。
- 认证绑定的 ESN 后 6 位。前端不得显示完整 39 位 ESN；完整值仅由服务层用于协议匹配、排序和日志关联。
- 发现阶段报告的当前 IP。
- 当前阶段和状态。
- Transfer 阶段显示接收进度条及百分比；其他阶段不显示进度条。
- 失败时显示由 `ErrorCode` 映射得到的当前语言简短文案；完整信息可通过提示或详情查看，但不得由服务层下发自由文本错误文案。

设备卡片不显示设备 ID，并采用隐藏 ID 后的紧凑行高。设备 ID 仅保留在服务层绑定、结构化失败信息和失败弹窗中。

解析阶段 CPDC 不持续上报解析状态或解析进度，因此 CPDS 不得显示“解析中”百分比或推测性进度。尚未收到最终解析结果的设备显示“等待解析结果”；收到最终成功或失败消息后再更新为“已完成”或“失败”。

CPDS 服务层向 UI 提供的会话字段 `activeState` 只允许以下稳定值，不写入 UDP 协议：

- `IDLE`
- `DISCOVERING`
- `AWAITING_DISCOVERY_CONFIRMATION`
- `AUTHENTICATING`
- `TRANSFERRING`
- `WAITING_PARSE`
- `DRAINING_AFTER_FAILURE`
- `COMPLETED`
- `PARTIAL_SUCCESS`
- `FAILED`

会话结果中的 `failures` 为数组，每项固定包含：

| 字段 | 说明 |
|---|---|
| `stage` | 失败所属发现、认证、传输或解析阶段 |
| `deviceType` | 失败设备类型，无法确定时为空 |
| `esnSuffix` | ESN 后 6 位，未知时为空；不得返回完整 ESN |
| `deviceId` | 已认证设备 ID，未绑定时为空 |
| `errorCode` | 统一 `ErrorCode` 枚举值 |
| `params` | 可选结构化参数对象，只允许路径、字段、期望值、实际值、上限、所需空间、可用空间、数量等原始数据，不得携带已拼接的自然语言句子 |

`activeState` 和 `failures` 属于 Android 应用内部 UI 模型，不得加入 Proto UDP 消息。`errorCode` 是 UI 与服务层之间唯一的失败语义，UI 不得依据自由文本推导状态或错误类型。阶段、设备类型、ESN 后 6 位、设备 ID 和错误参数等动态上下文使用上表的结构化字段传递，并由前端翻译模板通过参数插值生成完整句子。

CPDS Android 使用 `slang` / `slang_flutter` 或等价 Flutter 国际化方案，支持简体中文 `zh-CN`、英文 `en-US` 和阿拉伯文 `ar-SA`。默认语言为 `zh-CN`，任一翻译键缺失时回退到 `en-US`。所有用户可见文字，包括标题、按钮、菜单、表头、状态、校验提示、确认框、成功、部分成功和失败结果弹窗、计量单位和空状态，都必须提取为统一翻译键；包含文件名、数量、设备类型、ESN 后 6 位等动态内容的句子必须使用命名参数插值，不得通过字符串拼接生成。

初始化配置至少满足默认 `zh-CN`、回退 `en-US`，三套资源以完整语言标签注册，不使用只有 `zh/en/ar` 的短标签替代。语言切换菜单必须是可复用组件，切换后立即更新当前页面、设备状态和已经打开的确认或最终结果弹窗，不重新执行 Distribution。用户选择写入 `SharedPreferences` 键 `cpds.locale`，启动时优先读取有效保存值，无效值回退 `zh-CN`。每次初始化和切换都同步更新 Flutter `MaterialApp` 的 `locale`、`supportedLocales` 和 `Directionality`：中文、英文使用 LTR，阿拉伯文使用 RTL。

RTL 适配必须覆盖布局而不仅是文字翻译：使用 Flutter 方向感知的布局、对齐和图标翻转能力，阿拉伯语下 TopBar 操作顺序、侧边栏位置、内容区左右分栏、展开箭头、前进/返回类图标和弹窗对齐按阅读方向镜像，传输进度值本身仍从 0 递增到 100。不得在业务组件中散落针对阿拉伯语的硬编码像素覆盖。三份语言资源必须具有完全一致的键结构；自动化测试至少覆盖资源键一致性、默认与英文回退、即时切换、`SharedPreferences` 持久化、`Directionality` 同步、RTL 关键布局和带参数文案。

状态颜色：

| 状态 | 颜色语义 |
|---|---|
| 未发现/未开始 | 灰色 |
| 已发现/已认证 | 蓝色 |
| 接收中 | 橙色 |

## 5. 通信包导入与解析

### 5.1 导入校验

CPDS 必须校验整个通信包中的所有单位、节点和设备，不得只校验用户当前选择的节点。

#### 5.1.1 原始文件

1. 文件存在、可读取且大小大于 0。
2. 原始文件名是以 `.zip` 结尾的基本文件名，不得包含绝对路径、盘符、目录分隔符或 `..`。
3. 原始 ZIP 大小不超过 1 MiB（1048576 字节）。
4. 文件内容必须是合法 ZIP，不得只按扩展名判断。
5. Android 文件选择成功后，CPDS 将所选文件复制到应用私有 `uploads` 目录，并对保存后的原始文件计算 SHA-256；后续解析和下发必须使用这份已固定的文件，不能重新读取可能已被修改的用户源文件。

#### 5.1.2 ZIP 安全校验

1. 拒绝加密 ZIP。
2. ZIP 条目只允许普通文件和目录，拒绝符号链接及其他特殊文件。
3. 每个条目路径规范化后必须仍位于业务根内；拒绝绝对路径、盘符、路径穿越、空路径和 NUL 字符。
4. 拒绝规范化后路径重复的条目；为保证跨平台结果一致，也拒绝仅大小写不同但会形成同一路径的条目。
5. 读取每个普通文件直至结束并校验 ZIP CRC；CRC 失败时整个通信包无效。
6. 条目数量、压缩前后大小和累计值的计算必须执行整数溢出检查。
7. ZIP 普通文件与目录条目总数不得超过 4096，所有普通文件声明解压总量不得超过 64 MiB，单个普通文件不得超过 8 MiB，声明解压总量与 ZIP 原始大小之比不得超过 200:1；任一限制超出时以 `INVALID_ZIP_SIZE` 拒绝。
8. 规范化后的相对路径 UTF-8 长度不得超过 1024 字节，单个路径组件不得超过 255 字节。为保证跨平台行为一致，路径组件还必须拒绝保留设备名、冒号、末尾点号和末尾空格。

#### 5.1.3 业务根与目录

1. 必须存在 `0_contacts`、`3_device_config`、`4_net_node` 和 `6_unit`。
2. 包含任何无线电设备时，必须存在 `1_resource` 和 `2_radio_subnet`；一级资源目录统一且仅允许命名为 `1_resource`，不兼容其他名称。
3. `5_user` 允许存在，但本期不参与节点树展示。
4. 原始通信包不包含 `local_node.json`。该文件是 CPDC 生成 Server/IEC 输出包时增加的产物，CPDS 不识别、不解析、不校验其 JSON 内容，也不将其作为单位、节点、设备或引用关系的一部分。若输入 ZIP 意外携带该文件，只按普通 ZIP 条目执行通用路径、大小和 CRC 安全检查。
5. 原始业务目录应直接位于 ZIP 根。`txbz_json_v20.zip` 多出的一层顶级包装目录属于 CPDC 输出参考样例的历史缺陷，不作为 CPDS 原始导入格式；CPDS 不需要为了该输出样例兼容额外包装层。

#### 5.1.4 JSON 与引用关系

1. 业务目录内所有 JSON 文件语法正确，根结构和实现本期功能所需的关键字段类型正确；不影响本期规则的未知字段允许忽略。
2. `File.Guid` 允许是 JSON 数字或字符串，读取后统一转为字符串参与索引、比较和展示。
3. `0_contacts` 中 `UnitTree/SubUnits/NetNodes` 形成的单位和节点引用，必须分别解析到 `6_unit` 和 `4_net_node` 中的唯一文件。
4. 每个节点 `SystemConfiguration` 引用的设备文件必须存在于 `3_device_config/<deviceId>.json`。
5. 同一节点内设备 ID 原则上不得重复；每个 `(deviceType, deviceId)` 必须唯一。唯一例外是每个 `LANMember.CCU` 引用必须自动展开为类型分别为 `CCU` 和 `CCUAudio` 的两个逻辑设备，二者共享同一个原始 `dc_ccu_*` 设备 ID 和配置文件。CPDS 的列表、状态、发现投影、认证及结果关联必须使用 `(deviceType, deviceId)` 区分二者，不得只使用 `deviceId` 作为关联键。
6. 任一节点解析出的逻辑设备数量不超过 100；每个原始 CCU 引用展开后按两个逻辑设备计数。
7. 同一节点的 `SystemConfiguration.LANPrimary.Server` 不得同时引用 Server 和 IEC 设备；二者为业务互斥类型。

#### 5.1.5 设备类型与无线电依赖

1. 设备引用位置、文件名前缀和逻辑类型必须符合第 4.4 节映射表；前缀不匹配任何已知类型，或出现在错误引用位置时，通信包无效。
2. 无线电设备的 `Channels` 必须是 JSON 对象。每个频道中的 `Subnet` 必须是非空文件名主体，不得携带路径字符，并且必须存在唯一的 `2_radio_subnet/<Subnet>.json`。
3. 多个频道允许引用同一个 Subnet；该情况不视为错误，生成归档时按目标文件去重。
4. `MultiBandRadio` 和 `MultibandHandheld` 设备配置必须具有非空 `Alias`，用于生成 `PlanLocalUser`。
5. `HF` 和 `SmallHandheld` 首期按 MMR200 样例的公共字段结构校验，但不因缺少仅供 `PlanLocalUser` 使用的 Alias 而拒绝通信包。
6. 节点 ID、设备 ID 和原始文件基本名称的 UTF-8 长度不得超过 255 字节；Alias 不得超过 128 字节且不得包含 NUL、回车或换行，避免生成的 INI 结构被输入内容破坏。

只有通过文件、ZIP 安全、目录结构、全部 JSON、引用关系和业务字段校验的文件才能启用“下发”。校验失败时必须清空上一通信包的节点解析结果、禁用“下发”按钮，并使用 `errorCode + params` 显示具体文件、字段、引用路径和失败原因；普通 ZIP 或校验失败的 ZIP 不得发送到 CPDC，也不得进入任何 CPDC 正式输出目录。复制、计算 SHA-256、ZIP 读取和解析应采用流式处理，不得要求将整个 1 MiB 文件一次性载入内存。

### 5.2 ZIP 目录与磁盘空间预检

CPDS 在解压或解析前必须读取 ZIP 中央目录，累计所有普通文件声明的解压后大小，并估算本次处理所需空间：

`所需空间 = 原始 ZIP + 解压内容 + 所有暂存输出 + 20% 余量`

- 文件选择复制前，CPDS 根据所选文件大小检查应用私有临时落盘空间；复制完成并读取中央目录后，再按完整公式检查解压和暂存输出空间。任一检查不足都返回“导入失败：磁盘空间不足”，不得进入下发。
- Android 版不包含本机 CPDC，因此不适用“同设备 CPDC 所需空间的 2 倍”规则；仍按上述完整公式检查应用私有目录可用空间。
- 解压过程中必须累计每个文件和全包的实际解压字节数，并与 ZIP 声明值对比。实际值超过声明值、计算溢出、CRC 失败或超过已预留空间时立即终止并按无效通信包处理。
- 临时文件必须位于应用私有目录中已通过空间检查的位置；检查不得只针对共享存储总空间。
- 每次文件选择使用不可预测且与会话隔离的临时文件名，用户选择的原始文件名只能保存为元数据，不能直接作为临时路径。上传中断、大小超限、校验或解析失败时逐个删除本次明确命名的临时文件；新选择成功且当前无活动 Distribution 时逐个清理不再引用的旧临时副本。活动会话持有的不可变包副本在会话结束前不得清理或替换。
- CPDS 启动时逐个清理能够确认属于未完成选择或已结束会话的遗留临时文件；无法确认归属的普通文件只记录告警，不执行递归或目录级删除。日志不得记录用户原始完整路径。

### 5.3 解析结果

解析成功后，CPDS 应在内存中建立：

- 单位层级索引。
- 节点索引。
- 节点到期望设备类型、数量及设备 ID 的映射。
- 设备 ID 到设备配置文件的映射。
- 设备配置中可用于界面展示的 Alias、型号、目标 IP 等信息。

每个 `LANMember.CCU` 引用在期望清单中形成一项 `CCU` 和一项 `CCUAudio`。两项共享原始设备 ID，在右侧同一个“CCU”分组内分别显示为 `CCU-Main` 和 `CCU-Audio`，并分别展示各自 CPDC 实例的 ESN、IP、状态和进度。

选择当前节点后，右侧期望设备列表立即刷新，之前节点的发现和下发状态不得混入当前节点。

## 6. 下发入口与状态管理

“下发”按钮仅在以下条件同时满足时启用：

- 通信包解析成功。
- 已选择一个当前节点。
- 当前没有正在执行的下发会话。
- Android 已确定有效业务接口并完成所需网络权限申请。

点击“下发”后，CPDS 自动执行：发现 →（数量不匹配时等待用户确认）→ 认证 → 文件传输 → 等待 CPDC 解析 → 完成确认。每个 CPDC 在本机文件接收完成后可以立即解析，不必等待其他 CPDC 传输完成；CPDS 全局阶段仍保持“传输”，直至本次认证目标中的全部 CPDC 完成传输。CPDS 必须在任意全局阶段及时处理并 ACK 已经到达的解析最终结果。

点击“下发”时，CPDS 服务层必须为本次会话创建不可变输入快照，至少固定原始包临时副本路径、原始文件名、SHA-256、文件大小、`expanded_size`、`required_workspace`、当前节点、期望设备清单和认证绑定。会话运行期间不得重新读取用户源文件，也不得因页面重建、重新选择文件、重新解析或切换节点改变该快照。活动会话期间必须拒绝 Browse 选择提交、Parse 请求和节点切换请求；UI 同时禁用对应控件。该约束由服务层强制执行，不能只依赖页面按钮状态；同一 Android 应用进程全局只允许一个活动 Distribution。

发现阶段仅发生设备数量不匹配且至少存在一台可匹配在线设备时，CPDS 进入 `AWAITING_DISCOVERY_CONFIRMATION` 并弹出确认框；用户选择“继续”后只向匹配到的在线设备下发，选择“取消”则不进入认证并以失败结束本次 Distribution。没有任何可匹配在线设备时不显示数量确认框，直接以失败结束并显示一次最终失败弹窗。ESN 冲突、非法发现报文或认证失败仍立即结束并弹窗显示具体原因。

传输或解析阶段出现失败时，CPDS 把该设备标记为失败终态并继续处理其他非终态设备。本次认证目标全部进入终态后统一结算：没有任何设备下发成功时标记为 `FAILED`；至少一台成功，但存在未发现、被忽略或失败设备时标记为 `PARTIAL_SUCCESS`；只有发现数量完全匹配且全部目标设备均成功时才标记为 `COMPLETED`。设备下发成功以 CPDS 收到对应 CPDC 的成功 `PARSE_COMPLETE_REQ` 并将其记为成功终态为准。

设备一旦进入成功或失败终态，CPDS 不得使用该设备随后到达的 START 响应、进度、缺包或传输完成消息改写其终态；重复的 `PARSE_COMPLETE_REQ` 仍按幂等规则回复 ACK。CPDS 为其他非终态设备继续发送的广播不会要求终态 CPDC 再次参与，下一次 Distribution 从新的发现阶段和新的 `session_id` 开始。

CPDS 以 16 字节 UUID v4 `session_id` 隔离每次下发，会话结束后仍保留本次结果供用户查看。再次点击下发必须创建新 `session_id`。CPDS 与 CPDC 的 UDP 消息使用“4 字节 Magic 前缀 + `cpd.proto` 定义的 Proto3 二进制 `Packet`”封装，不使用 JSON 或 gRPC。Magic 固定为 `0xEEDDCCBB`，按网络字节序编码为 `EE DD CC BB`。

每条逻辑消息首次发送时生成一个 16 字节 UUID v4 `message_id`；同一逻辑消息的广播副本、环回副本和定时重发复用相同 ID 及相同消息体，新逻辑消息使用新 ID。RSP 或 ACK 直接复制触发它的 NTY 或 REQ 的 ID，不增加 `nty_message_id`、`req_message_id` 或 `ack_message_id`。`message_id` 只用于关联和幂等，不作为设备身份、安全凭据或额外业务判定条件。

CPDS 发送的 `TRANSFER_START_NTY` 必须携带原始文件名和 32 字节原始 SHA-256。CPDC 会维护最近一次接收并校验成功的 `./txbz/` 原始包缓存：缓存文件名和实际哈希均匹配时可以跳过文件接收，并以 `TRANSFER_STAGE_CACHE_REUSE` 返回成功 `TRANSFER_COMPLETE_RSP`；CPDS 在设备状态和日志中显示“复用已接收原始包”。缓存命中只优化传输，本次认证、成功应用快照、节点 ID、设备 ID 和文件包即使全部一致，CPDC 也必须使用缓存包实际执行本次完整解析，不得直接回复解析成功。

CPDS 收到某 CPDC 成功的 `TRANSFER_COMPLETE_RSP` 后，一律为该实例启动独立 35 秒解析结果等待计时，为 CPDC 的 30 秒本地解析期限以及结果发送、调度留出余量。重复的传输完成回复不得重置计时。35 秒内收到有效最终 REQ 时立即停止计时并回复 `PARSE_COMPLETE_ACK`：`result=RESULT_SUCCESS` 时标记该实例成功终态；`result=RESULT_FAILED` 时标记该实例失败终态，并记录统一错误码。35 秒内没有收到有效最终结果时，以 `PARSE_TIMEOUT` 标记该实例失败终态。迟到的有效 `PARSE_COMPLETE_REQ` 仍需回复 ACK 以停止 CPDC 重发，但不得改写已经确定的超时失败终态。其他设备仍在传输、补发或解析不得暂停或重置该计时；单个实例解析失败或超时不得终止其他非终态设备。

成功 `PARSE_COMPLETE_REQ` 表示 CPDC 已经写入全部正式输出并更新成功快照，ACK 只表示 CPDS 已经收到该结果。CPDS 发送 ACK 后无法判断 ACK 是否被 CPDC 收到，不得把“CPDC 未确认收到 ACK”列为服务端失败条件。成功和失败共用 `PARSE_COMPLETE_REQ/PARSE_COMPLETE_ACK`，不定义独立解析失败消息。

## 7. 发现与认证显示需求

### 7.1 发现结算与数量确认

CPDS 在 5 秒发现窗口内每隔 1 秒广播一次 `DISCOVER_NTY`，在第 5 秒结束前不提前进入认证。窗口结束后，按当前节点解析出的设备类型及数量，与窗口内所有 `DISCOVER_RSP` 中的逻辑设备类型及数量统一比较：

- 类型和数量完全一致：发现成功，直接进入认证。
- 仅存在缺少设备、多出设备或各类型数量不一致：进入数量不匹配确认流程，不立即发送认证消息。
- ESN 冲突、非法设备类型或发现报文无效：发现失败，不允许继续下发。

数量不匹配确认框必须明确提示“设备数量与发现设备数量不匹配，是否继续下发？”，并按设备类型显示期望数量、发现数量、缺少数量和多出数量。存在至少一台可匹配在线设备时提供“继续”和“取消”：选择“继续”后冻结本次精简目标清单，只对按照第 7.2 节规则匹配到的在线设备执行认证、传输和解析；多出的发现设备不生成认证记录、不接收文件并从本次下发中忽略。选择“取消”时不发送 `AUTH_NTY`，本次任务完成并标记为失败。没有任何可匹配在线设备时不显示该确认框，直接把任务标记为失败并显示一次最终失败弹窗。

最终结果按成功设备数量和发现差异统一判定：没有任何设备最终成功时标记为失败；至少一台成功，但存在未发现、被忽略或失败设备时标记为部分成功；数量完全匹配且全部设备成功时才标记为全部成功。因此，用户在数量不匹配确认框选择“继续”后，即使精简目标清单内全部设备成功，本次任务仍为部分成功。

多类型 CPDC 共享一个 ESN，但其 `DISCOVER_RSP.device_types` 中每个类型分别计为一个逻辑设备。CPDS 同时记录发现回复直接携带的 `instance_nonce/current_ip/subnet_mask`；这三个字段不要求出现在后续阶段消息中。

`CCU-Main` 与 `CCU-Audio` 不是同一多类型 CPDC 的两个身份，而是两个分别运行的 CPDC 实例。前者配置 `deviceTypes: ["CCU"]`，后者配置 `deviceTypes: ["CCUAudio"]`，二者必须使用各自独立的 ESN。对于每个包内 CCU 引用，数量完全匹配要求同时发现一台 `CCU` 和一台 `CCUAudio`；任一类型缺少、多出或数量不一致均进入相同的数量不匹配确认流程。

每收到一条合法发现回复，CPDS 必须立即把该实例按既定的“设备类型内 ESN 升序 × 通信包设备顺序”规则临时投影到右侧期望设备列表，实时显示已上线数量、ESN 后 6 位、当前 IP 和“已发现”状态。临时投影只用于界面显示，不生成认证绑定，也不允许提前结束完整 5 秒发现窗口；进入数量确认或发现最终失败时仍保留本轮已经发现的设备信息供用户判断和排查。

同一发现窗口内，相同 ESN 且 `instance_nonce` 不同表示不同运行实例发生 ESN 冲突，CPDS 在第 5 秒统一结算时把本次发现标记为失败。弹窗显示冲突 ESN 后 6 位、各实例 IP、设备类型和足以区分实例的 nonce 摘要，并提示运维人员停止其中一台 CPDC、将其 `cpdc_config.json.esn` 清空后重新启动。CPDS 不得发送要求 CPDC 自动更换 ESN 的网络消息。

### 7.2 自动配对

同一设备类型存在多个实例时：

1. 在线 CPDC 实例按固定 39 位 ESN 字符串升序排列。
2. 通信包内设备保持 `SystemConfiguration` 数组原始顺序。
3. 两个列表只在共同索引范围内一一绑定；缺少的期望设备保持未发现，多出的在线实例不绑定并从本次下发中忽略。

认证后，CPDS 服务层维护最终 ESN—设备 ID 绑定关系；右侧设备项只更新 ESN 后 6 位、IP 和状态，不显示设备 ID。

CPDS 生成认证记录后、首次广播前必须执行唯一性校验：

- 每个 `(deviceType, ESN)` 只能对应一个 `deviceId`。
- 每个 `(deviceType, deviceId)` 只能对应一个 ESN。
- 同一 ESN 可以对应不同 `deviceType`，用于多类型 CPDC，但每种类型只能有一条绑定。
- 认证记录数量和类型计数必须与本次冻结的认证目标清单一致；数量完全匹配时该清单等于当前节点期望清单，用户确认继续后该清单只包含已匹配在线设备。

校验失败时 CPDS 在本地以 `AUTH_ASSIGNMENT_CONFLICT` 终止认证，不发送存在冲突的 `AUTH_NTY`。CPDC 仍执行相同的防御性检查。CPDS 收到 `result=RESULT_FAILED` 的 `AUTH_RSP` 时立即认证失败，不等待普通认证超时；`error_code=ERROR_CODE_AUTH_CONFLICT` 时显示冲突绑定，`ERROR_CODE_BUSY` 时显示由当前语言资源映射的“设备仍在处理上一会话”。协议不定义独立的认证冲突或忙碌消息。

认证记录编码后的单个 UDP 负载不得超过 1400 字节，其中 Magic 占 4 字节、Protobuf Packet 最多 1396 字节。全部认证记录无法放入一条消息时，CPDS 按 `4 + proto.Size(Packet)` 和完整记录边界生成多条相互独立的 `AUTH_NTY`，每条消息包含一部分完整认证记录。认证从第 0 秒开始发送完整一轮；尚未结束时在第 1、2、3、4 秒分别重发完整一轮。认证记录不得跨消息截断，也不增加分片编号或重组字段。

5 秒是认证最大窗口而非固定等待时间。全部预期 CPDC 返回成功 `AUTH_RSP` 时立即进入 Transfer，不再发送剩余认证轮次；任一失败 `AUTH_RSP` 立即导致认证失败；到第 5 秒仍缺少成功回复时以认证超时失败。发现阶段仍必须完整等待 5 秒，不允许提前成功。

CPDS 使用本项目自己的协议常量文件集中定义发现、认证、传输及等待解析结果等时间参数，不依赖 CPDC 源码。UI 所需倒计时或状态时间由服务层提供，不得在页面组件中硬编码时间数值。

## 8. 文件传输显示需求

- CPDS 默认按 1 Mbit/s 名义文件负载速率对 UDP 数据分包进行节流，不得无节流地瞬间发送整个通信包；实际有效速率可以因系统调度、丢包和补发而降低。该值在 CPDS 工程自己的传输常量文件中以 `TransferPayloadRateBitsPerSecond = 1_000_000` 集中定义，不属于 CPDC 配置或双方协议协商字段。
- 进度条只在 Transfer 阶段显示；发现、认证、解析和完成阶段均不显示任何发送或设备进度条。
- Transfer 阶段在阶段条下方显示独立的“CPDS 发送进度条”，并同时显示已发送分包数/分包总数和百分比。
- 首轮发送进度按“首轮已发送分包数/分包总数”连续计算；它不代表任何一台 CPDC 的接收进度。
- 首轮发送完成后，发送进度保持 100%。进入缺包补发时，进度条旁改为显示“补发中”和当前待补发分包数量，不重新从 0% 开始。
- 每台 CPDC 的接收进度以 CPDC 报告的约 30%、60%、100% 为准。
- CPDC 报告缺包时，对应设备显示“补发中”及已知接收进度。
- 首轮数据发送期间不执行 10 秒设备静默计时。第一次发送 `TRANSFER_END_NTY` 后，每个 CPDC 使用单调时钟分别启动自己的 10 秒回复计时器。
- 只有某设备自身的有效回复可以重置该设备的 10 秒计时器。CPDS 发送 START、END、收到其他设备回复或为其他设备补包，均不得重置或暂停该设备计时器。
- CPDS 正在补发某设备自身请求的缺失分包时，只暂停该设备的 10 秒计时器；该轮补发结束并发送 END 后恢复计时。其他设备的计时器继续运行。
- 首轮数据发送前连续广播 2 次 `TRANSFER_START_NTY`；数据发送持续超过 1 秒时，发送期间每 1 秒补发一次开始通知。
- 首轮发送结束后再次广播 2 次 `TRANSFER_START_NTY`，再广播 `TRANSFER_END_NTY` 并进入设备结果等待状态。
- 等待结果期间需要重试时，每 1 秒按顺序发送一次 `TRANSFER_START_NTY + TRANSFER_END_NTY`，不能只发送结束通知。
- 每轮缺包补发完成后发送一次 `TRANSFER_START_NTY + TRANSFER_END_NTY`。
- 任一必需 CPDC 返回 `result=RESULT_FAILED` 的 `TRANSFER_COMPLETE_RSP` 时，CPDS 将该设备标记为失败终态并停止仅针对该设备的补发，同时记录其阶段、错误码和原因；PRECHECK 阶段常见原因包括包大小或开始参数非法、认证绑定缺失和磁盘空间不足，RECEIVE/VERIFY 阶段还包括文件读写、大小及哈希失败。CPDS 继续完成其他非终态设备。
- 第一次 END 后，某设备连续 10 秒没有自身有效回复时，将该设备标记为传输失败终态；不能用其他设备的消息替它续期。
- CPDS 根据某设备最新进度回复和缺包区间计算其唯一有效接收分包数并维护接收高水位。某设备虽持续有效回复，但高水位连续 30 秒没有增加时，将该设备以“传输无进展”标记为失败终态；只要高水位继续增加，缺包补发不限制轮数。
- 只要仍收到缺包回复，CPDS 持续补发，不限制补发轮数。
- `TRANSFER_END_NTY` 消息体为空；文件名、大小、SHA-256 和分包总数只取自当前会话 START。单个 CPDC 使用多条 `TRANSFER_LOSSPACK_REQ` 上报缺包区间时，每条都是可独立处理的完整请求。CPDS 不回复 ACK，收到有效 REQ 后立即把区间并入待补发集合，不等待分片重组；重复区间必须幂等合并，丢失 REQ 由下一次 END 触发的重新检查覆盖。

CPDC 解析成功还必须满足以下正式输出约束，任一步失败均通过 `PARSE_COMPLETE_REQ` 报告解析失败，CPDS 不得把该设备标记为成功：

- `CCU` 在 `./txbz_ccu/` 生成对应 `dc_ccu_*.json` 后，只删除相对 CPDC 可执行文件目录的 `../../update/` 直属目录下匹配 `dc_ccu_*.json` 的普通文件，不递归且不处理子目录或其他文件；随后将配置复制到该目录并递归清空、保留 `./txbz_ccu/` 根目录，成功时配置只保留在 `../../update/`。`CCUAudio` 的目标目录是 `../update/`，写入前执行相同的匹配文件清理规则。
- `Server` 和 `IEC` 在保留现有 `./txbz_server/<原始通信包文件名>` 输出的同时，都递归清空并保留相对 CPDC 可执行文件目录的 `../txbz_data/` 根目录，再按原始通信包文件名去掉末尾 `.zip` 扩展名创建子目录，将包含本次 `local_node.json` 的各自完整输出包解压到 `../txbz_data/<原始通信包文件名去掉.zip>/`。
- `./txbz_ccu/` 和 `../txbz_data/` 的递归清理删除目标根目录内全部文件和子目录，但不删除根目录本身；清理、复制或解压不建立回滚机制，失败时不得更新成功应用快照。

## 9. 结果弹窗与失败原因

每次 Distribution 进入终态都必须显示与结果对应的最终弹窗：

- 全部成功：显示下发成功摘要，并增加提示“请重启通信参数下发成功的相关设备。”
- 部分成功：显示导致未全部成功的数量不匹配和/或设备失败信息，并分别列出成功完成、失败、未发现以及被忽略的多出设备；同时增加提示“请重启通信参数下发成功的相关设备。”
- 失败：发现或认证阶段失败时立即弹窗；传输或解析阶段先在页面显示“已检测到设备失败，正在完成其他在线设备”，待本次认证目标中的全部 CPDC 进入成功或失败终态后再弹出最终汇总。失败弹窗至少显示失败阶段、失败设备类型、ESN 后 6 位（已知时）、设备 ID（已绑定时）、统一错误码和具体原因，并分别列出成功完成、失败和掉线的全部设备。

数量不匹配确认框属于发现阶段决策弹窗，不替代最终结果弹窗；用户选择“取消”后还必须显示最终失败弹窗。无可匹配设备时不显示数量确认框，直接显示一次最终失败弹窗。

典型原因包括：

- 通信包格式无效或引用文件缺失。
- 通信包超过 1 MiB、ZIP 声明大小异常或磁盘空间不足。
- 发现阶段缺少某类型设备或数量不匹配。
- 发现到当前节点不需要的额外设备类型。
- 不同 CPDC 实例使用相同 ESN。
- 认证回复缺失。
- 认证记录唯一性校验失败，或 `AUTH_RSP` 返回 `AUTH_CONFLICT/BUSY` 失败码。
- 文件传输阶段设备失联。
- 文件传输阶段设备持续回复但连续 30 秒接收高水位没有增加。
- 文件大小、分包或整体哈希校验失败。
- CPDC 通过 `result=FAILED` 的 `PARSE_COMPLETE_REQ` 上报解析失败。
- 某 CPDC 在收到其 `TRANSFER_COMPLETE_RSP` 后的 35 秒内未上报有效 `PARSE_COMPLETE_REQ`。

## 10. 日志

CPDS 应记录：

- 包导入和解析结果。
- 当前节点及期望设备清单。
- 每个阶段的开始、成功、失败时间。
- CPDC 发现信息和最终绑定结果。
- 分包发送、缺包区间和补发轮次。
- 每台设备的进度与解析结果。
- 所有失败原因。

日志文件保存在应用私有目录，不写入共享存储，不记录用户原始完整路径。CPDS 日志和前端可显示的结构化上下文统一执行以下脱敏规则：

- 不记录 `1_resource` 中的密钥正文，也不记录设备配置中的密码正文，包括 `AdvancedPassword` 和 `PrimaryPassword`。
- 对字段名包含 `password`、`passwd`、`secret`、`privateKey` 或明确表示密钥内容的字段，按大小写不敏感规则把字段值替换为 `***`；脱敏必须在结构化数据序列化为日志或错误文本之前完成。
- 不记录原始 UDP 分包负载、完整 ZIP 内容或完整 JSON 正文。
- JSON 解析失败时只记录文件路径、字段路径、错误类型和位置，不输出可能包含敏感内容的原文片段。
- 前端弹窗及发往 CPDC 的结构化协议字段不得包含密钥或密码正文；Proto 失败消息只携带 `ErrorCode`，不携带自然语言原因。
- 文件名、设备 ID、节点 ID、SHA-256 和分包序号允许正常记录。

## 11. 验收标准

1. CPDS Android 能正确解析按本规范使用 `1_resource` 且业务目录直接位于 ZIP 根的原始通信包；`txbz_json_v20.zip` 只作为 Server/IEC 的 CPDC 输出产物参考，不属于 CPDS 原始导入包验收范围。
2. 左侧导航仅显示“参数加注”，节点树能按样例包显示单位和网络节点；选择 A车后右侧显示一台 MMR200、一台 Server，以及一个包含 `CCU-Main` 和 `CCU-Audio` 两行的“CCU”分组，共四个逻辑设备。手机纵向和横屏布局均不丢失该信息。
3. 右侧设备卡片不显示设备 ID，能清晰显示设备名称、ESN 后 6 位、IP 和状态；仅 Transfer 阶段显示 CPDS 发送进度和设备接收进度。
4. 每秒发送一次 `DISCOVER_NTY`，完整等待 5 秒后统一判断全部 `DISCOVER_RSP`；数量不匹配且存在可匹配设备时弹出继续/取消确认框，继续后只向匹配在线设备下发，取消后不发送认证消息并以失败结束；无可匹配设备时不显示确认框，直接显示一次最终失败弹窗。
5. 认证、传输、解析状态与交互流程文档一致。
6. 首轮发送无 10 秒静默超时；第一次 END 后每个 CPDC 独立累计 10 秒自身回复计时，只在补发该设备自身请求的分包期间暂停。其他设备的回复、补发或 CPDS 发送 START/END 不得替它续期。
7. 缺包持续存在时能够持续补发，不受固定轮数限制。
8. 除发现数量不匹配确认框中的“取消”外，下发过程中界面不提供暂停、取消或终止操作；Android 系统返回键不得退出活动 Distribution。
9. Android 通过同一 Wi-Fi 或 USB 以太网二层广播域能够完成发现、认证、接收和解析；蜂窝、VPN 或热点共享接口不参与发送。
10. Android 活动 Distribution 以前台服务运行；应用退到后台或切换任务后，UDP 会话仍可继续，并在通知栏显示进行中状态。
11. CPDC 在全局传输阶段提前通过 `PARSE_COMPLETE_REQ` 上报成功或失败时，CPDS 能够立即返回 `PARSE_COMPLETE_ACK` 并正确更新对应设备状态。
12. Android 通过系统文件选择器选择 1 MiB 以内的 ZIP 时，CPDS 以流式方式复制、校验和解析，不依赖客户端原始完整路径，也不要求 `MANAGE_EXTERNAL_STORAGE`。
13. 认证记录超过单个 1400 字节 UDP 负载时能够生成多条独立 `AUTH_NTY`，CPDC 从这些消息中正确累计自己的多类型绑定。
14. 缺包区间超过单个 1400 字节 UDP 负载时能够按 `4 + proto.Size(Packet)` 生成多条独立 `TRANSFER_LOSSPACK_REQ`；CPDS 不回复 ACK，逐条幂等合并并只补发所有 CPDC 实际缺失分包的并集。
15. `LANPrimary.Server` 只引用 `dc_server_*` 或只引用 `dc_IEC_*` 时分别识别为 Server 或 IEC；同一节点同时引用两种前缀时导入失败并显示互斥冲突。
16. 普通 ZIP、缺少业务目录的 ZIP、设备引用缺失或关键业务字段无效时，导入失败且“下发”按钮不可用；该文件不会发送到 CPDC 或进入任何 CPDC 正式输出目录。
17. 原始 ZIP 超过 1 MiB 时导入失败；ZIP 中央目录声明异常、空间计算溢出或磁盘空间不足时显示明确的“导入失败”原因。
18. CPDS 在解压前完成应用私有目录空间预检，解压期间累计实际写入量；实际写入超过目录声明或预留量时停止处理，不产生可下发结果。
19. Android 版不包含本机 CPDC，不要求按所需空间 2 倍预检；仍必须按原始 ZIP、解压内容、暂存输出和 20% 余量完整预检。
20. CPDS 发送前检测到认证映射不唯一时，不发送认证消息并以 `AUTH_ASSIGNMENT_CONFLICT` 失败；收到 `ERROR_CODE_AUTH_CONFLICT` 或 `ERROR_CODE_BUSY` 的失败 `AUTH_RSP` 时立即失败，不等待认证窗口超时。
21. 对小于 1 秒即可完成首轮发送的包，即使 CPDC 丢失首部两次 `TRANSFER_START_NTY`，仍能依靠尾部开始通知、结束通知和全量缺包补发完成传输。
22. Android 活动会话期间系统返回键、侧滑返回或页面内退出入口不得终止进程；应用进入后台必须由前台服务保证会话继续。强制停止或卸载按异常中断处理。
23. 某 CPDC 返回成功 `TRANSFER_COMPLETE_RSP` 后 35 秒内未上报有效 `PARSE_COMPLETE_REQ` 时，CPDS 以 `PARSE_TIMEOUT` 把该设备记为失败终态并继续完成其他非终态设备；迟到结果只 ACK、不改写终态，最终会话不会永久停留在等待解析结果状态。
24. `PARSE_COMPLETE_REQ` 使用 `result=SUCCESS/FAILED` 统一表达解析成功和失败，CPDS 对两种结果均返回 `PARSE_COMPLETE_ACK`。
25. CPDS 发送成功结果 ACK 后即按已送出确认处理；无法获知 CPDC 是否实际收到 ACK，不把 ACK 送达状态作为 CPDS 侧失败条件。
26. `TRANSFER_START_NTY` 携带 32 字节原始文件 SHA-256，`TRANSFER_END_NTY` 消息体为空；CPDS 不发送或等待 `TRANSFER_LOSSPACK_ACK`。
27. 某 CPDC 缓存文件名和实际 SHA-256 匹配时，CPDS 接受其缓存复用传输结果并等待本次重新解析；即使缓存、认证和成功应用快照全部匹配，也不接受未实际解析就直接上报的成功结果。
28. CPDS 发送时在序列化 Packet 前拼接大端 Magic `EE DD CC BB`；接收时先校验 Magic，不匹配则直接丢弃，匹配后才反序列化 Packet。Packet 不超过 1396 字节，完整 UDP 负载不超过 1400 字节，Packet 内部不包含 `magic/version/timestamp/nty_message_id/req_message_id`。
29. ESN 冲突、非法发现报文或认证失败时立即结束并弹窗；发现数量不匹配按确认结果处理。传输或解析阶段某设备失败时继续完成其他非终态设备，待本次认证目标全部进入终态后统一结算：零台成功为失败，部分设备成功为部分成功，只有数量完全匹配且全部设备成功才为全部成功。
30. 第一次 END 后，持续回复但连续 30 秒唯一有效接收分包数没有增加的设备以“传输无进展”失败；其他在线设备继续完成传输和解析。
31. 加密 ZIP、符号链接、路径穿越、规范化后重复路径、仅大小写不同的冲突路径或 CRC 错误均导致导入失败，且不产生可下发结果。
32. CPDS 校验通信包中的全部节点；未选择节点中的引用缺失或业务字段错误同样导致导入失败。
33. `File.Guid` 分别使用 JSON 数字和字符串时均可解析，并规范化为相同字符串语义。
34. 多个无线电频道引用同一个有效 Subnet 时导入成功，生成归档只包含一份对应文件；`Radio.MR9360` 和 `Radio.PRR206` 分别按 HF 和 SmallHandheld 识别。
35. 构造包含 `AdvancedPassword`、`PrimaryPassword` 及大小写不同敏感字段名的设备配置和解析错误时，CPDS 日志和弹窗中的结构化上下文均只显示脱敏值，不出现原始正文；协议只传错误码。
36. 认证未完成时在第 0 至 4 秒每秒发送一轮全部 `AUTH_NTY`；全部成功回复到齐时立即进入 Transfer，失败回复立即失败，第 5 秒仍不完整时认证超时。
37. 修改 CPDS 自己的协议时间常量文件后，CPDS 所有相关计时行为同步变化；UI 和服务层不存在第二份硬编码协议时间，也不依赖 CPDC 工程文件。
38. 两个不同 nonce 实例报告相同 ESN 时发现失败，弹窗提供可区分实例的信息及人工清空其中一台 ESN 的恢复说明；CPDS 不会要求设备自动改号。
39. CPDS 导入校验拒绝同一节点同时存在 Server 和 IEC 的通信包。
40. 默认 1 Mbit/s 时，1 MiB 通信包首轮发送约 8.39 秒且不会触发传输静默超时；修改 CPDS 的 `TransferPayloadRateBitsPerSecond` 后无需修改 CPDC。
41. CPDS 向 UI 返回的 `activeState` 只使用规定枚举；失败详情固定包含 `stage/deviceType/esnSuffix/deviceId/errorCode` 及可选结构化 `params`，不返回完整 ESN 或自由文本错误原因。
42. 每个非零 `ErrorCode` 在三套语言资源中都有文案；Distribution 结束后切换语言可以立即重绘当前成功、部分成功或失败弹窗，协议和服务层无需重新提供错误字符串。
43. 同一逻辑消息的广播、环回和重发复用一个 `message_id`，RSP/ACK 复制触发消息的 ID；系统不定义额外 ID 字段，也不把 ID 用于业务身份或安全判断。
44. Android 版本保留环回副本发送逻辑；未部署本机 CPDC 时不影响远端流程，环回失败只记录告警。
45. `zh-CN`、`en-US` 和 `ar-SA` 语言资源键结构完全一致；默认中文、缺失键回退英文，切换语言后页面和已打开弹窗立即更新，重启后从 `cpds.locale` 恢复选择。
46. 切换阿拉伯语后 Flutter `Directionality` 和本地化组件完成 RTL 切换，TopBar、侧边栏、左右内容区、对齐、间距及方向性图标完成镜像；切回中文或英文时恢复 LTR。
47. 自动化测试覆盖翻译键一致性、默认与回退、语言即时切换、持久化、方向同步、RTL 关键布局和带参数错误文案；所有用户可见硬编码文字检查通过。
48. 活动 Distribution 期间，任何页面重建、文件重选、重新解析或节点切换请求都不能替换会话包；当前会话始终使用点击下发时冻结的不可变输入快照。
49. CPDC 进入认证失败、传输失败或解析终态后，CPDS 继续为其他设备发送的旧会话消息不会使其重新参与；下次只通过新 `session_id` 的发现通知重新开始。
50. ZIP 条目数、声明解压总量、单文件大小、压缩比、路径长度和跨平台路径名称超过规定上限时导入失败，不创建可下发结果。
51. Android 存在一张候选 Wi-Fi 或有线接口时自动选择；存在多张候选时恢复仍有效的 `cpds.networkInterface`，无有效历史选择时禁用“下发”直至用户选择。应用重启后选择保持有效。
52. Android 每条逻辑消息无论候选接口数量多少都只发送一个环回副本，业务接口副本和环回副本复用相同 `session_id/message_id`，重复到达不会重复更新状态或分包进度。
53. Android 接口初始化或发送失败且存在其他可用候选接口时，用户选择或刷新后的替代接口可继续 Distribution；没有可用接口或当前接口发送失败时以 `NETWORK_INTERFACE_ERROR` 失败并显示具体原因。
54. Android 接收端监听 `0.0.0.0:39002` 且不读取到达网卡索引；通过 Magic、Proto 结构、当前 `session_id`、阶段和设备身份绑定丢弃无效报文，本次会话中不因接口增删重新扫描。
55. Android 候选接口枚举不得把蜂窝、VPN、热点共享、环回、链路本地或虚拟接口作为业务接口；Wi-Fi 与 USB 有线接口在具有私有 IPv4 时允许入选。
56. CPDS Android 无需启动参数即可打开；页面在右侧当前节点标题栏下方显示“业务接口”下拉框、“刷新”和“下发”，其他控件样式保持不变。
57. Android 只有一张候选业务接口时自动选中；多张候选时恢复仍有效的 `cpds.networkInterface`，无有效历史选择时禁用“下发”直至用户选择。横竖屏切换后选择保持有效。
58. 点击“刷新”后候选接口列表与操作系统当前状态一致；已选接口消失时不得继续使用陈旧选择，枚举失败或无可用接口时显示三语 `NETWORK_INTERFACE_ERROR`。
59. 活动 Distribution 期间 Android 接口下拉框和“刷新”按钮不可操作，本次会话始终使用点击“下发”时冻结的单一业务接口。
60. 接口选择不增加 Proto 字段，也不改变 CPDS 与 CPDC 交互消息。
61. CPDS 根目录 `version.json` 是唯一产品版本来源；Android TopBar 在品牌名称旁显示 `CPD V<主版本.次版本.修订版本.构建版本>`，版本配置缺失或不符合四段数字格式时构建失败。
62. Android 的 UDP 广播、环回或接收套接字初始化失败、MulticastLock 获取失败或本地网络权限被拒绝时，前端统一显示当前语言的 `NETWORK_INTERFACE_ERROR`，不得显示 `INVALID_MESSAGE`。
63. 每个 `LANMember.CCU` 引用自动生成共享原始设备 ID 的 `CCU-Main` 和 `CCU-Audio` 两项，单节点数量按两项计算；右侧在同一个“CCU”分组内显示两项及两个独立 ESN 的状态，任一类型数量不匹配时进入相同的继续/取消确认流程。
64. `CCU` 写入相对其可执行文件目录的 `../../update/`、`CCUAudio` 写入 `../update/` 前，只删除各自目标目录直属、匹配 `dc_ccu_*.json` 的普通文件，不递归且不影响子目录或其他文件；只有配置复制成功且 `./txbz_ccu/` 递归清空后才上报解析成功。
65. `Server` 和 `IEC` 都只有在保留 `./txbz_server/` 输出并把包含本次 `local_node.json` 的各自完整输出包解压到递归清空后的 `../txbz_data/<原始通信包文件名去掉.zip>/` 后才上报解析成功；例如 `txbz_123.zip` 解压到 `../txbz_data/txbz_123/`。清理或解压失败时 CPDS 接收失败结果并正确显示。
66. 每次 Distribution 按成功设备数量统一结算：零台成功为 `FAILED`；至少一台成功但存在未发现、被忽略或失败设备时为 `PARTIAL_SUCCESS`；只有数量完全匹配且全部设备成功时为 `COMPLETED`。数量不匹配后继续时，多出的发现设备不接收任何认证或文件消息。
