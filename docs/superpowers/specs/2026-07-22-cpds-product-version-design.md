# CPDS 产品版本展示设计

## 目标

为 CPDS 增加统一的产品版本配置，并在 TopBar 的 `CPD` 品牌名旁显示当前版本。首个版本值为 `0.1.0.1`，界面完整文本为 `CPD V0.1.0.1`。Windows 桌面版与 CCU 浏览器版必须显示同一版本。

## 范围

- 在 CPDS 仓库根目录增加唯一的产品版本配置文件 `version.json`。
- Vite 构建从该文件读取版本，TopBar 不保存另一份硬编码版本号。
- Windows 桌面版和 CCU 浏览器版共用该前端构建结果，因此使用相同版本。
- 更新 `01-CPDS-requirements.md`，并同步修改 CPDS、CPDC 两个仓库中的对应需求文档。
- CPDC 没有 TopBar，本次不修改 CPDC 程序代码。

## 版本配置

根目录 `version.json` 使用以下结构：

```json
{
  "version": "0.1.0.1"
}
```

版本必须是四段非负十进制数字，格式为 `主版本.次版本.修订版本.构建版本`。配置只保存数字部分；大写 `V` 是界面展示前缀，不属于版本值。

Vite 配置在构建启动时读取并校验该字段，再通过编译期常量提供给 Vue。配置缺失或格式非法时，开发与正式构建都应立即失败，不能生成无版本或错误版本的产物。

## TopBar 展示

`TopBar.vue` 在现有品牌名后增加独立的版本元素，内容为 `V` 加编译期产品版本。品牌名仍由国际化资源提供，版本标识不翻译、不随语言变化。

版本元素紧邻品牌名，字号和视觉权重低于 `CPD`，但保持清晰可读。布局继续使用逻辑属性和现有弹性布局，中文、英文及阿拉伯语环境下均不增加按语言硬编码的定位规则。

## 构建数据流

1. 开发服务器、前端测试或正式构建启动。
2. Vite 读取根目录 `version.json` 并校验四段式版本。
3. Vite 将版本注入前端编译环境。
4. TopBar 渲染 `CPD V0.1.0.1`。
5. Windows 桌面版和 CCU 浏览器版打包同一份前端资源，因此版本保持一致。

运行时不调用 Go 接口获取版本，避免增加无必要的接口、异步加载状态和失败分支。

## 测试与验收

- 先增加失败测试，证明 TopBar 当前尚未显示产品版本。
- 测试从统一配置读取的版本为 `0.1.0.1`，且格式符合四段式规则。
- 挂载 Dashboard/TopBar 后断言品牌区域显示 `CPD V0.1.0.1`。
- 检查版本元素使用独立样式，并保持在品牌容器内。
- 运行全部前端测试、前端正式构建、Go 测试和静态检查。
- 运行 CPDS 完整构建脚本，确认 Windows 与 CCU 两个构建产物均能成功生成。
- 比较 CPDS 与 CPDC 的对应需求文档，确认内容一致。

## 非目标

- 不增加 CPDC 的图形界面或版本展示。
- 不增加在线更新、版本协商或协议版本字段。
- 不通过后端 API 动态修改版本。
- 不把四段式产品版本强行写入 npm 的三段式包版本字段。
